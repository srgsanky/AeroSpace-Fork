// tag::purpose[]
:manpurpose: Move workspace to monitor targeted by relative direction, by order, or by pattern.
// end::purpose[]

// =========================================================== Synopsis
== Synopsis
[verse]
// tag::synopsis[]
aerospace move-workspace-to-monitor [-h|--help] [--workspace <workspace>] [--swap] [--wrap-around] (left|down|up|right)
aerospace move-workspace-to-monitor [-h|--help] [--workspace <workspace>] [--swap] [--wrap-around] (next|prev)
aerospace move-workspace-to-monitor [-h|--help] [--workspace <workspace>] [--swap] [--] <monitor-pattern>...

// end::synopsis[]

// =========================================================== Description
== Description

// tag::body[]
{manpurpose}
Focus follows the focused workspace, so the workspace stays focused.

Without `--swap`, the command fails when the moved workspace's xref:guide.adoc#assign-workspaces-to-monitors[monitor force assignment] disallows the destination.
When exactly two monitors are connected, `--swap` validates both workspace assignments before either workspace is moved, so a disallowed assignment fails without changing either monitor.

// =========================================================== Options
include::./util/conditional-options-header.adoc[]

-h, --help:: Print help
--swap:: When exactly two monitors are connected, exchange the moved workspace with the target monitor's active workspace instead of replacing the source monitor's workspace with an invisible stub workspace.
In that case, the workspace being moved must be visible.
With any other number of monitors, this option uses the normal move behavior.
--wrap-around:: Allows to move workspace between first and last monitors

--workspace <workspace>::
include::./util/workspace-flag-desc.adoc[]

// =========================================================== Arguments
include::./util/conditional-arguments-header.adoc[]

(left|down|up|right)::
Move workspace to monitor in direction relative to the focused monitor

(next|prev)::
Move the workspace to next or prev monitor.
'next' or 'prev' monitor is calculated relative to the monitor `<workspace>` currently belongs to.

<monitor-pattern>::
Find the first matching monitor and move the workspace there.
Multiple monitor patterns is useful for different monitor configurations.
Monitor patterns follow the same format as in `workspace-to-monitor-force-assignment` config option

The default configuration swaps the focused workspace with the other monitor when exactly two monitors are connected, and uses the normal move behavior otherwise:

[source,toml]
----
alt-shift-tab = 'move-workspace-to-monitor --swap --wrap-around next'
----

Existing configuration files must update this binding manually.
